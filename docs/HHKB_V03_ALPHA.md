# HHKB v0.3-alpha custom slots

This alpha keeps the hardware-verified v0.12 executable/core unchanged and edits only
the eight 8-byte descriptors plus HFB CRC fields.

## Current scope

- Up to 8 enabled slots.
- Source and tap key selectable from the verified HHKB physical-index map.
- Hold action is fixed LeftCtrl.
- Per-slot threshold is configurable.
- Custom-slot builds use **Build & Validate**; only the exact SHA-locked validated build can enable **Flash validated build**.
- The bundled v0.12 baseline is SHA-locked to:
  `cc4cd8b7aafbfd2ce1ae3895685dac5ddc74abd62113a50e8d2d2cf141f4ca25`

## LSHIFT

LSHIFT is intentionally not selectable in v0.3-alpha. Hardware testing confirmed
physical source index `0x00` and hold-to-Ctrl works, but v0.12's release-time tap
semantics do not preserve normal Shift chord behavior. Modifier-aware dual-role is
deferred to v0.13 rather than changing the known-good v0.12 core.

## Safety

The descriptor builder refuses an unknown baseline SHA and audits that only the HFB
CRC header and 64-byte descriptor table differ from the locked baseline.

## Validated Flash gate

The GUI stores the exact SHA-256 of the build that passed descriptor/diff/CRC validation.
Any slot edit disarms Flash. Immediately before USB I/O, the helper re-reads the HFB,
checks the expected SHA, verifies the bundled baseline SHA, rejects every byte difference
outside HFB[0:4] and the 64-byte descriptor table, and recomputes both CRCs.

A real flash also requires typing a SHA-derived confirmation token. The helper implements
only the application update path E0/E1/E2/E3 and retains packet ACK/counter checks and
post-E3 reconnect verification from the hardware-tested writer.

## alpha3 UX changes

## alpha5 — generic HOLD

The HHKB custom-slot path now uses the hardware-tested v0.13 rev2.2 generic-HOLD core.

Descriptor layout:
- +0 enabled
- +1 Source physical index
- +2 Tap physical index
- +3 Hold physical index
- +4/+5 threshold ms
- +6 slot metadata
- +7 reserved

GUI safety rules:
- Hold may not equal Source.
- Hold may not be any enabled dual-role Source.
- LSHIFT/RSHIFT/FN are blocked as Hold targets.
- LSHIFT remains blocked as Source/Tap because its tap semantics are not validated.

Representative hardware validation before alpha5:
- ordinary Hold target: V
- modifier Hold target: LeftCtrl
- second modifier family: LeftAlt
- physical/synthetic ownership overlap was validated on the tested targets.

The bundled baseline is SHA-locked to the rev2.2 LeftAlt test image. Custom builds change
only the descriptor table and CRC fields relative to that baseline; executable code is
not regenerated by the GUI.


## alpha6 — HOLD validation status

GUI-only/support-metadata refinement over alpha5. The generic-HOLD executable baseline is unchanged.

HOLD classifications:
- HW VALIDATED: CTRL, LALT, V, SPACE
- GENERIC / LIMITED TESTING: other selectable HOLD targets
- BLOCKED: LSHIFT, RSHIFT, FN

The selected HOLD status is shown beside each slot and is included in Build & Validate output.
The alpha5 hardware-validated 3-slot configuration A→CTRL, C→LALT, V→SPACE remains representable
without executable-code changes.
